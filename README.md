# MICU 화재대피 웹앱 v0.7.3 RC

기존 배치 결과를 유지하면서 근무표 해석·배치 계산을 분리하고, 등록 전 확인과 전체 데이터 백업·복원을 추가한 로컬 검토본입니다. RC는 최종 배포 전 검증본이라는 뜻입니다. 실제 휴대폰 검증이 남아 있으므로 FINAL로 표시하지 않습니다.

## 실행과 확인

```sh
npm start
```

브라우저에서 `http://127.0.0.1:8071`을 엽니다. 실행에는 Python 3가 필요하며 npm 패키지 설치는 필요 없습니다. XLSX 라이브러리는 `vendor/`에 있습니다. 웹 URL 실행을 기준으로 하며 `file://` 저장은 보장하지 않습니다. 외부 배포는 이번 작업에서 수행하지 않았습니다.

개발 검사는 다음 명령으로 실행합니다.

```sh
npm ci --ignore-scripts
npm run check
npm test
python3 scripts/package-release.py
```

## 사용 흐름

1. **근무표 → ＋ 근무표 저장**에서 Excel을 선택합니다. 아직 저장되지는 않습니다.
2. 연월·시트·날짜 행·이름 열·선임 그룹 인원과 읽힌 표를 확인합니다. 필요하면 날짜 행과 이름 열을 지정합니다. 비워 두면 자동 감지합니다.
3. 날짜·듀티별 배치 예상 결과와 경고를 확인하고, 원본 대조 확인란을 선택해 저장합니다. 설정을 바꾸면 확인란이 해제됩니다.
4. 근무표 목록의 **사용**으로 적용합니다. 저장과 사용은 별개입니다.
5. 인원 관리의 추가·삭제는 선택한 날짜·듀티에, 이름·직종·선임 그룹 수정은 해당 근무표 전체에 적용합니다. 변경사항 저장을 눌러 확정합니다.
6. 배치 화면의 직접 이름 수정은 그 날짜·듀티의 표시 이름만 바꿉니다. 자동 배치보다 수동 수정이 우선합니다.

현재 기본 규칙은 선임 간호사 1명이 통보연락반, 다음 2명이 소화반, 나머지 간호사와 추가 사원·의사가 대피유도반입니다. D/E/N/NC를 근무로 읽고 NC는 N으로 처리합니다. 같은 그룹에서는 원본 행 순서를 유지합니다.

기존 파일에서 선임 그룹을 알 수 없으므로 처음 8명은 Charge, 다음 6명은 중간년차, 나머지는 저연차라는 기존 가정을 유지합니다. 미리보기에서 수를 바꿀 수 있습니다. 이는 공식 양식·운영 규칙의 승인을 의미하지 않습니다.

## 전체 백업과 복원

**전체 백업 · 복원**에서 JSON 파일을 내려받습니다. JSON은 데이터를 문자로 보관하는 파일 형식입니다. 근무표·인원 변경·수동 배치·활성 근무표·이력이 포함되며 샘플 인원 수정도 포함됩니다. 원본 Excel 파일 자체나 실행 프로그램은 포함하지 않습니다.

복원할 파일을 선택하면 크기·형식·검증값·인원 연결 관계를 검사합니다. 현재 데이터를 별도로 백업하고 다운로드 완료를 확인한 뒤 확인란을 선택해야 복원할 수 있습니다. **복원은 이력을 포함한 전체 교체이며 병합이 아닙니다.** 성공 후 전체 복원과 저장 성공 이력을 추가합니다.

다른 탭에서 미리보기 이후 데이터가 변경되면 복원을 중단합니다. 복원 전에 열린 탭은 새로고침 전까지 쓰기를 차단합니다. 전체 복원은 다섯 저장 영역을 하나의 트랜잭션으로 교체합니다. 트랜잭션은 묶인 작업이 모두 성공하거나 모두 취소되도록 하는 저장 단위입니다. 완료 후 다시 읽어 일치를 확인합니다.

복원 쓰기 완료 후 다시 읽기에 실패하면 결과 확인이 필요하다고 표시합니다. 이때 복원을 반복하지 말고 새로고침해 내용부터 확인합니다. 복원 전 백업을 보관합니다.

백업은 최대 20MB이며 암호화되지 않습니다. 이름·근무 정보가 들어 있으므로 보관·전달 대상을 확인해야 합니다. SHA-256은 파일 변경·손상을 확인하는 검증값입니다. 신원 인증이나 위변조 방지 서명이 아닙니다. 브라우저는 다운로드 요청 후 파일이 실제 보관됐는지 앱에 보장하지 않으므로 다운로드 목록을 직접 확인합니다.

## 저장 호환성

- 기존 IndexedDB 이름 `fireEvacuationRosterDB_v0617`을 유지하고 내부 구조 버전을 4로 올립니다. v2·v3 데이터를 유지하는 자동검사가 있습니다.
- IndexedDB는 브라우저 안에 있는 데이터베이스입니다. 같은 사이트 주소·브라우저 프로필에만 저장하며 기기 간 자동 동기화는 없습니다. 주소의 호스트·포트가 달라도 저장공간이 달라집니다.
- `rosters`, `personnel`, `overrides`, `meta`, `logs`에 각각 근무표, 인원 변경, 수동 배치, 관리 정보, 이력을 보관합니다.
- 일반 저장은 완료 후 다시 읽어 확인합니다. 실패 시 입력을 유지합니다. 이력 저장 실패는 운영 데이터 저장 실패와 구분해 재시도할 수 있습니다.
- 일반 근무표 교체·삭제는 그 근무표의 인원 변경·수동 배치를 초기화하며 이력은 보존합니다. 전체 백업 복원만 이력까지 교체합니다.
- localStorage는 v0.7.0 자료의 일회성 이전에만 사용합니다. 정상 저장 성공을 대신하는 보조 저장소로 사용하지 않습니다.
- **DB v4를 연 사이트에서 v0.7.2 이하를 그대로 실행하는 다운그레이드는 지원하지 않습니다.** 이전 앱 ZIP 보관과 브라우저 운영 데이터 백업은 별개입니다.
- 사이트 데이터 삭제·저장소 정리·기기 고장은 쓰기 확인만으로 막을 수 없습니다. 정기적인 파일 백업이 필요합니다.

## 개발자가 수정할 위치

| 위치 | 책임 |
| --- | --- |
| `domain/config.js` | 버전별 양식·배치 규칙 설정 |
| `domain/roster-parser.js` | 셀 배열 해석, 날짜·이름·코드 검증 |
| `domain/roster-model.js` | 현재 근무자, 자동 배치, 사람 ID, 수동 배치 재연결 |
| `domain/change-events.js` | 저장 전후 데이터의 차이를 이력 사건으로 변환 |
| `domain/backup-format.js` | 백업 형식·검증값·복원 데이터 검사 |
| `ui/import-review.js` | Excel 선택과 미리보기·확인 화면 |
| `ui/backup-panel.js` | 백업 다운로드·복원 확인 화면 |
| `storage.js` | IndexedDB 저장·이전·충돌 방지·전체 복원 |
| `audit.js`, `history.js` | 공통 이력 기록·재시도와 이력 조회·내보내기 |
| `script.js`, `personnel.js` | 화면 상태·기존 배치 화면·인원 관리 연결 |
| `data/sample-roster.js` | 가상 샘플 자료 |

새 규칙은 기존 설정을 덮어쓰지 않고 새 ID의 프로필을 추가합니다. 프로필은 규칙 값을 묶은 설정이며, 새 근무표에는 당시 규칙의 복사본을 저장합니다. 이미 저장한 근무표는 새 기본값 때문에 몰래 바뀌지 않습니다. 자세한 예시는 `docs/ARCHITECTURE_v0.7.3.md`에 있습니다.

최소 실행 파일은 `index.html`, `style.css`, 루트 JS 6개, `domain/`, `ui/`, `data/`, `vendor/`입니다. 모든 경로를 함께 보관합니다. 서버/API를 붙일 때에는 저장 경계를 교체하고 인증·권한·동시 편집을 별도로 설계해야 합니다.

검증 결과와 남은 항목은 `TEST_REPORT.md`, 사용자 변경 보고는 `RELEASE_REPORT_v0.7.3.md`, 실제 휴대폰 절차는 `docs/MOBILE_ACCEPTANCE_v0.7.3.md`를 참조합니다. 실제 운영 Excel이나 브라우저 백업 JSON은 앱 ZIP에 넣지 않습니다.
